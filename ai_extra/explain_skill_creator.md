
### Explain 관련 스킬 생성기

- Explain 서비스 관련 스킬을 생성할 때, 지켜야할 지침을 정리해둔다.
- 로컬과 실제 URL 관련해서 스킬을 나누어 만든다. _local.md , _url.md 로 한다.

### 공통 지침

- 스킬은 명세다. 등록·활성화하기 전에는 자동 실행되는 것이 아니며, 문서에는 등록된 범위만 자동화라고 쓴다 (AGENTS.md).
- 모든 스킬은 `ai_extra/<영역>/SPEC.md`의 성공 기준 항목과 연결한다. 연결되지 않은 스킬은 만들지 않는다.
- 결과에는 `mode`(local|url), `verification`(verified|unverified|blocked), 근거를 붙인다.
- 검증은 pass / fail / blocked로 남긴다. 실행하지 않은 항목은 완료로 쓰지 않는다.
- 탐색·후보·생성 결과는 행동 모델(페르소나) 입력에 넣지 않는다. 문제 정답을 주입하지 않는다.
- 실제 API 호출은 키·모델·호출 범위를 확인한 뒤 명시적으로 실행하고, 고정 정책·SDK mock 결과와 구분해 기록한다.
- 세션별 브라우저·기억·출력 격리와 종료 상태(성공·가상 이탈·기술 실패 등) 구분을 유지한다.

### 로컬 / URL 구분 기준

- **local = 타겟의 프론트 소스 코드를 읽을 수 있는 경우.** 코드가 1차 근거다.
- **url = 실행 중인 화면만 볼 수 있는 경우.** 화면 탐색이 1차 근거다.
- 모드는 "소스 접근 가능 여부"로 판정한다. 코드 경로가 주어지고 읽을 수 있으면 local, 아니면 url이다. 둘 다 있으면 local로 시작하고 URL 화면으로 교차 확인한다.
- 이 구분은 "자동 테스트를 어디서 돌리나"와 별개다. 자동 테스트·검증 fixture는 AGENTS.md대로 우리 로컬 모의 사이트로 제한한다 (모의 사이트는 코드와 정답을 모두 알고 있어 local 스킬의 검증 대상으로 쓴다).

### _local.md 작성 규칙

- 대상: 소스 코드를 읽을 수 있는 타겟의 프론트 구현 코드.
- 코드에서 1차로 뽑는 것: 라우트 선언, 화면 컴포넌트, 이동(navigate/Link/redirect), 폼·필수 입력·검증 규칙, 조건부 렌더링 분기, API 호출, 사용자 노출 문구, 반응형 기준(breakpoint).
- 읽기 전용이다. 타겟 코드를 수정하지 않고, 코드 안의 비밀값·환경변수·개인정보는 산출물에 옮기지 않는다.
- 코드만으로 확정할 수 없는 항목(동적 라우트 값, 서버 응답에 따른 분기, 런타임 조건부 렌더링, 모달·다단계 폼)은 `needs_gui_check`로 표시하고 화면 실행으로 확인한다. 확인 못 한 항목은 완료로 세지 않는다.
- 근거는 파일:줄 단위로 남긴다 (후보·단계·원인마다 어느 코드에서 나왔는지).
- 코드에서 읽은 정보도 행동 모델(페르소나)에 주입하지 않는다. 집계·라벨링·범위 제안에만 쓴다.
- 프레임워크별 규칙은 `skills/front_framework/`에 파일로 분리한다 (예: react_router_local.md, nextjs_local.md). 어떤 프레임워크인지는 package.json·설정 파일로 먼저 판정한다.
- 스킬 자체의 검증은 정답을 아는 우리 모의 사이트(코드·정답 보유)에서 재현율·정밀도로 측정한다. 실개인정보·실결제·운영 계정 자료는 fixture에 넣지 않는다.

### _url.md 작성 규칙

- 대상: 실제 URL. 모드 판정은 origin 기준이고, 모르면 url(fail closed)로 처리한다.
- 읽기 전용이 기본이다. 비가역 행동(제출·결제·가입·로그아웃·삭제)은 하지 않고, 경계 노드에서 멈춘다.
- 허용 origin, 깊이, 페이지 수, 요청 간격, LLM 호출 상한을 정책(ExplorePolicy)으로 명시한다.
- 로그인은 등록된 테스트 계정 세션으로만 진입한다. 로그인·결제 벽은 우회하지 않고 blocked로 기록한다.
- 정답이 없으므로 결과는 unverified이고 사용자 승인 후에만 revision으로 확정한다. 자동 테스트는 정제한 오프라인 스냅샷 replay로 하고 실사이트를 대상으로 하지 않는다.
- 실개인정보가 포함될 수 있는 캡처·스냅샷은 저장 전에 제거한다.

### 파일 구조

```
ai_extra/
  <영역>/SPEC.md            # 목적·하드코딩 현황·원칙·Subagent·SKILL·Workflow·성공 기준
  skills/
    <영역>_local.md
    <영역>_url.md
    front_framework/        # 로컬 정적 분석 규칙 (프레임워크별)
```

### SPEC.md 템플릿

```
<제목> (<현재 고정> → <자동화 후>)
목적:
현재 하드코딩 (자동화 대상)  # 파일:줄 단위로 적는다
원칙
Subagent    # 입력 / 수정 범위 / 인계 산출물, 검증 에이전트는 분리
SKILL       # 로컬 / URL / 공통
Workflow
성공 기준 (각 항목은 pass / fail / blocked로 기록)
```
