원인 후보 자동화 (3종 고정 분류 → 근거 기반 가변 후보)

목적: 가상 이탈의 원인을 코드에 박힌 분류·문구로 판정하지 않고, 세션 근거(화면·행동·좌절 신호)에서 원인 후보를 도출한다. 후보는 가설이며 사람이 확인한 원인과 구분한다.

현재 하드코딩 (자동화 대상)
- agent/persona_report.py:11 CATEGORIES — input_burden / navigation / cost 3종만 존재
- agent/persona_report.py recommendation() — 원인·단계별 개선 문구 if/else
- agent/persona_dashboard.py — 'cost' 판정이 문구 '배송비 3,500원이 추가됩니다.' 일치 여부에 의존
- agent/frustration.py PARAMETERS — 가중치(입력 16, 재방문 8, 탐색 10, 비용 40)와 임계치가 미보정 상수
- agent/human_alignment.py:6 CAUSES — 9종(input_burden, navigation, cost, value, trust, technical, accessibility, unknown, none)으로 리포트 3종과 불일치
- agent/README.md "7종 원인 분석" — 7종의 목록이 문서에 정의돼 있지 않음 (확인 필요)

원칙
- 원인은 확정이 아니라 후보다. 후보마다 근거(단계·화면 캡처·행동·신호값)를 반드시 붙이고, 근거가 없으면 후보를 만들지 않는다.
- 기술 실패(agent_failure, site_failure, budget_exceeded, cancelled, blocked_auth)는 UX 원인 후보에서 제외한다.
- 후보 분류 체계(taxonomy)는 하나로 통합하고 리포트·Human Alignment가 같은 목록을 읽는다.
- 분류는 알려진 후보 + unknown을 허용하고, 정답 원인(문제 정답)을 행동 모델에 주입하지 않는다.
- 사람 관측 데이터는 비교용이다. 보정 반영 여부는 D04 K04 확인 전까지 반영하지 않는다.
- 로컬은 정답 원인이 알려진 모의 사이트로 평가하고, URL 결과는 unverified로 표시한다.

Subagent

- 원인 후보 에이전트 1종 (읽기 전용): 세션 trace·캡처·신호를 입력받아 후보·근거·신뢰도를 산출한다.
  - 입력: 종료된 세션 기록(단계, 행동 trace, 좌절 점수 구성, 문제 시점 PNG), 단계 레지스트리
  - 수정 범위: 없음, 후보 산출물만 쓴다
  - 인계 산출물: 후보 목록(category, stage, evidence[], confidence, 대안 후보), unknown 사유
- 검증 에이전트는 별도로 두고 정답 원인과 비교만 한다. 후보 에이전트의 모델·프롬프트는 검증 에이전트에 공유하지 않는다.

SKILL

- 로컬(_local): 타겟 소스 코드를 읽을 수 있을 때, 세션 근거(이탈 단계·화면)를 해당 화면의 코드와 연결해 원인 후보를 좁히는 스킬. 코드에서 필수 입력 수·검증 규칙·비용 계산 위치·노출 문구·분기 조건을 읽어 후보의 근거(파일:줄)로 붙인다. 코드 근거는 후보를 뒷받침하는 정보이지 원인 확정이 아니다. 스킬 검증은 원인을 알고 있는 우리 모의 사이트(problem 케이스)와 비교해 한다.
- URL(_url): 코드를 볼 수 없고 정답이 없으므로 근거 일관성(같은 세션을 여러 번 분석했을 때 후보 일치)과 사람 검수를 쓰는 스킬. 결과는 unverified.
- 공통: 후보 도출은 결정적 신호(필수 입력 수, 재방문, 스크롤, 노출 비용 요소)를 먼저 쓰고, LLM은 화면 근거 해석과 문장화에만 쓴다. 실제 API 호출은 키·모델·호출 범위를 확인한 뒤에만 실행한다.

Workflow

1. 종료 세션 분류: 가상 이탈만 대상, 기술 실패·한도·인증 차단은 분리.
2. 신호 추출: 단계별 필수 입력 수, 재방문, 탐색 스크롤, 예기치 않은 비용 요소 등 결정적 신호를 계산한다. 비용 요소는 고정 문구가 아니라 화면 텍스트의 금액·수수료 패턴으로 감지한다.
3. 후보 생성: 신호와 근거 화면으로 후보를 만들고 unknown을 허용한다.
4. 근거 검증: 근거 캡처가 없으면 최종 화면으로 대체하지 않고 누락을 표시한다.
5. 묶기: 과업·단계·원인 기준으로 이슈를 묶는다 (이슈 단위 정의는 D04 P12 확인 필요).
6. 개선 가설 연결: 후보별 개선 문구를 규칙표에서 가져오되 가설로 표시한다.
7. 확정: 로컬은 정답 비교 통과 시 확정, URL은 사용자 검수 후 확정한다.

성공 기준 (각 항목은 pass / fail / blocked로 기록)

- [ ] 원인 분류 체계가 한 곳에서 정의되고 리포트·Human Alignment가 같은 목록을 쓴다
- [ ] 로컬 문제 fixture에서 심어둔 원인의 후보 재현율·정밀도가 기준 이상 (기준값 정하기)
- [ ] 후보가 없거나 근거가 부족하면 unknown으로 남고 임의 원인을 만들지 않는다
- [ ] 모든 후보에 근거(단계·캡처·신호값)가 연결된다
- [ ] 같은 세션을 N회 분석했을 때 후보 일치율이 기준 이상
- [ ] 비용 요소 감지가 특정 고정 문구 없이 문구가 다른 fixture에서도 동작한다
- [ ] 기술 실패가 UX 원인 후보에 섞이지 않는다
- [ ] 후보·정답 원인이 행동 모델 입력에 포함되지 않는다 (계약·테스트로 확인)
- [ ] URL 결과는 unverified로 표시된다
- [ ] "7종 원인"의 정의를 확정했다 (현재 미정의)
